### H2 — HIGH: half of every generated quote file was discarded, by a counter nothing read

**Claimed.** `feeds.CsvQuoteFeed`'s docstring: *"Rows that do not parse are counted in `unparsed`
rather than dropped quietly — a malformed quote file that silently yields no coverage would read as
a vendor coverage failure and be reported against Q1, which is the wrong finding."*

**Actually.** The generator wrote each sample as `f"{base_time}T09:{30+minute:02d}:00+00:00"` for
`minute` in `range(60)`, so the second half of every bar was timestamped `09:60` through `09:89`.
`datetime.fromisoformat` rejects those, `_parse` returns `None`, and `unparsed` increments. **4,620
of 9,240 rows — exactly 50% — never reached the measurement, and nothing printed the counter.**

**Reproduced by execution.** `CsvQuoteFeed(Path("data/spike2a/quotes.csv")).unparsed` → `4620`
against 9,240 rows in the file; 30 distinct invalid timestamps, `09:60` … `09:89`.

This is the fifth defect class in its third population. The first was a mechanism built and not
called; the second a parameter registered and read by nothing; this is **a diagnostic computed,
kept current, and never read.** `tests/test_enforcement.py` cannot see it for the same structural
reason it cannot see the second: nothing is violated, so there is no violation to attempt.

**Disposition — fixed.** `divmod` for the minute arithmetic; `q4_spreads.main` prints the unparsed
share; `CsvQuoteFeed` gained `rows_read` so a count can be reported as a share. The guarantee-test
convention now has a corollary worth writing down: **a counter no caller prints is not a
diagnostic**, and the way to test one is to assert the caller reports it.

### H3 — HIGH: R was derived by hand, and correcting it changed the §7 verdict

**Claimed, three times.** `scripts/spike2a/README.md`'s second "obligation the schemas cannot
enforce": *"`signal_bars.r` must come from the library's own stop functions … an R computed by hand
means Q4 measures a stop rule that is not the shipped one."* `q4_spreads.SignalBar`'s docstring:
*"if it ever computes it by hand, Q4 is measuring a stop rule that is not the shipped one. That is
the single most likely way for this measurement to be quietly wrong."* And
`synthetic_data_generator.generate_signal_bars`'s own docstring, at `:164`: *"The R value is computed
using the library's own stop functions, per §4.3."*

**Actually.** `synthetic_data_generator.generate_signal_bars` computed `stop = price * Decimal("0.97")`
(or `0.96`, or `0.975`), `entry = price * Decimal("1.005")`, `r = entry - stop`. It imported
`gates.apply_stop_floor_and_ceiling` at module scope and never called it — which is why the unused
import was one of H1's ruff failures. The function whose absence was the defect was sitting in the
import block.

**Reproduced by execution**, and quantified: **154 of 154** R values were not whole ticks (nor were
any of the 154 prices — 43 to 52 decimal places, 48 being the commonest, from
`Decimal(random.uniform(...))`); **7** were below `min_stop_distance` = 0.10, which the library's
floor would have raised. On row 0 the
hand-rolled stop was `7.587411…` where the library gives `7.58`, an R of `0.2334` against `0.2408`
— **3.1% low.** Recomputed row by row against `apply_stop_floor_and_ceiling`: **6 of the 154 raw
stops the generator invented are rejected outright by the library** (all `STOP_TOO_WIDE`, all on
sub-$1.90 names — so six bars existed in the sample that the shipped stop rule would never have
produced); across the other 148 the understatement runs **0.014% to 7.7%, median 1.4%**, with four
rows over 5%. The signal-time cap is `max_spread_r × R`, so **every cap in the run was tight by its
own row's error** — a distribution rather than a constant, which is harder for a measurement to
survive than a uniform bias would be.

**And it changed the answer.** Same generator, same seed, only the stop derivation and the tick
alignment corrected:

| | §7 Q4 verdict | Aggregate | Cheapest decile |
|---|---|---|---|
| Before | **INERT** — "every decile below 2% — the gate is decoration" | 0.00% (0/154) | 0.00% |
| After | **CALIBRATED** | 1.36% (2/147) | **14.29%**, all VWAP Reclaim |

Both numbers are statements about a random number generator and neither is evidence about
`max_spread_r`. What matters is the sensitivity: a defect in the instrument moved the verdict across
a §7 threshold boundary, and the INERT branch prints *"An inert gate is documented as inert, not
left reading as protection"* — an instruction to go and change a document.

**Disposition — fixed.** The stop goes through `apply_stop_floor_and_ceiling`; entry and price are
tick-aligned so R is a whole number of ticks by construction; bars the library rejects are dropped
rather than clamped. Post-fix: 0 of 147 R values off-grid, 0 below the floor, 0 off-grid quotes.

### H4 — MEDIUM-HIGH: Q4 attributes one quote to up to three setups, an hour after the signal

`load_signal_bars` takes `samples[-1]` as "the quote in force at the signal instant", on the stated
assumption of one sample per bar. The generator supplies 60 per bar, and `CsvQuoteFeed` keys by
`(symbol, session_date)` with no setup and no instant — so a symbol-session firing three setups
produces one key holding all three bars' samples, and all three setups are gated on the same last
one.

**Reproduced by execution at `3545adf`:** 46 symbol-sessions carried more than one setup, covering
**98 of 154 bars**, and in all 46 every setup received the identical quote; the sample used was
`09:59`. Note the interaction with H2 — at `3545adf` a three-setup key held 90 parseable samples of
180 written, not 180, because the `09:60`–`09:89` half never parsed; after H2's fix it is 180. The
post-fix figures are 44 symbol-sessions and 94 of 147 bars, and the sample used is `10:29`, the true
end of the sampled hour. Per-setup reporting is the reason Q4 exists — A21's concern is setup-specific,
and `MVP_SETUPS` is cut three ways for exactly that reason.

**Open.** The fix is a schema decision, not a line: either `signal_bars.csv` carries the signal
instant and the feed selects the last quote at or before it (which is §20.14's actual rule), or
`quotes.csv` carries the setup. Both change the documented input schema, and choosing needs the
vendor's tick shape, which is unknown. Recommended for the same change as H6.

### H5 — MEDIUM-HIGH (spec question): §7's sample definition is implemented in two halves nothing joins

§7: *"Every symbol-session **in the two windows** that passes the selection rule below, capped at
**400** symbol-sessions."* `windows.select_windows` computes the windows; `universe.select_sample` applies the filters
and the cap. **`select_sample` has no window parameter, and no module composes them.**

**Reproduced by execution.** On the repository's own `vix.csv` the rule selects
`2026-07-07..2026-07-20` (mean VIX 23.78) and `2025-09-10..2025-09-23` (14.16). The generated
`preopen.csv` spanned `2026-07-02..2026-07-29`: **79 of 156 rows fell outside both windows, and the
selected quiet window contained none at all.** `universe.py` reported `156 rows parsed / 156
included / 0 rejected` — a clean-looking result over a population §7 does not define.

Two separate problems, and only one is fixed. The generator picked its windows by calendar recency
while writing the VIX series that `windows.py` reads; that is fixed here — it now calls
`select_windows` on the series it just wrote. **The missing join in the code is not fixed**, because
where it belongs is a scope decision: inside `select_sample` (which makes that module the definition
of the sample and changes a documented signature), in a new composing module (which is the first
step of the accretion §8 forbids), or in the collection script §7 assumes and the repository does
not contain. Raised in [docs/CHANGELOG.md](../CHANGELOG.md) under Unreleased.

### H6 — MEDIUM: §20.14's validity half cannot fire on the shipped input

`q4_spreads.classify` calls `quotes.spread_at_signal`, which is `check_quote` plus a subtraction, and
the module documents this as applying "the §20.14 validity tests". On CSV input those tests cannot
fail:

- `age_seconds` is `Decimal(row.get("age_seconds") or 0)` (`feeds.py:124` at `3545adf`, `:128` after
  this change added `rows_read`) and the column is optional, so every quote from a file that omits it
  is asserted to be **0 seconds old** — including the `09:59` quote H4 shows being used for an
  `09:30` signal. §20.14 staleness is unreachable.
- `bid_size`/`ask_size` are drawn from `randint(100, 10000)` against `min_quote_size` = 100, so the
  odd-lot branch is unreachable.
- `bid < ask` by construction, so `QUOTE_CROSSED` is unreachable.

**Reproduced by execution:** `reason counts: {'PASS': 154}` at `3545adf`. Every §20.14 rejection
branch that `q4_spreads` advertises was unexercised, and the one branch that could have fired was
told the quote was fresh.

## 5. What is genuinely good

Not padding. Four things in the new code are better than the standard this review is applying.

**`prereg.py` is the right answer to a problem most projects get wrong.** §7's thresholds are held
as `int` percents and counts, converted at the comparison site by `pct()`, specifically so that no
`Decimal("0.30")` can be mistaken for a threshold restatement — and the numeric collisions with
registered defaults are enumerated in the docstring. That the enumeration was wrong (H9) is a
one-line defect inside a design that is exactly right.

**`q4_spreads.verdict` orders its clauses deliberately and says why.** The cheap-stock decile clause
is checked *before* the inert test, with a comment stating that reversing the two lines "would
reproduce A21 while reporting that A21 did not occur." That is the polarity discipline of §20.13
applied to a control-flow decision, and the corrected run vindicated it: 1.36% aggregate against
14.29% in the cheapest decile is precisely the case the ordering exists for.

**`feeds.py` argues against its own promotion.** A `Protocol` appeared where the PLAN predicted, and
the module docstring spends a paragraph explaining why it must stay out of `src/tradipy/` until a
vendor is chosen. Code that anticipates its own misuse and refuses the upgrade is rare.

**`PreOpenFacts.check_units()` is a guarantee test written before the guarantee was violated.** It
rejects fractions supplied as whole percentages, on the reasoning that `12 >= 0.04` is true for
every row — so the gap filter would keep reporting that it filtered while rejecting nothing. It
caught a real instance immediately. This is convention 6 applied to an input contract, and it is the
one place in the spike where the instrument checks itself.

## 6. The risk the findings list does not capture

**Five of this project's six checks point at `src/tradipy/` and the PRD. The sixth points at the
code that produces the measurement — and it is the one whose output nobody read.**

That second sentence is the correction that matters, and an earlier draft of this section got it
wrong by claiming no check ranged over `scripts/`. One does: `d2e94a4` extended the registry lint's
roots precisely so that it would, and `test_the_lint_scans_scripts_recursively` exists to keep it
there. It worked. It failed the build, named the file and named the parameter. **What the exemption
in §8 leaves uncovered is everything else** — the worked-example fixtures, the boundary and polarity
assertions, the enforcement fixtures and the doc-count test do not range over `scripts/`, and 123 of
the suite's 126 functions have nothing to say about it.

So the class has two halves and both are needed to produce H3. The five checks that could have
caught a wrong derivation are pointed elsewhere by design — the deliberate consequence of §8
exempting the spike from coverage, for the correct reason that coverage obligations are how
throwaway code becomes permanent. And the one check that *was* pointed at the spike was a pytest
test in a repository whose pre-commit hooks do not run pytest, so its verdict reached nobody. The
cost of the exemption was invisible until there was spike code to pay it, and this round is the
invoice: three HIGH findings, one of them verdict-changing, in the code that decides whether a
shipped threshold is right.

The concrete danger is short and specific. Q4 comes back RECALIBRATE or INERT. D7 says raise it as a
spec decision rather than apply it — good. The spec decision is then argued from a number produced
by code with no test obligation, no coverage, no derivation assertion, and a demonstrated history of
being 3% off in a way that crossed a §7 boundary. The review apparatus that would catch a bad
threshold *in the PRD* has nothing to say about a bad measurement *of* the PRD.

The mitigation is not more review. It is one rule, and it is cheap: **any value capable of triggering
a D7 disposition must derive from the library rather than restate it, and must be reproducible from
an input whose provenance is declared.** H3 is what happens without the first half; H7 is what
happens without the second.

Second risk, unchanged and still the largest in absolute terms: **no version of this repository has
been read by anyone without prior context.** Three code rounds have now been performed by readers
with the repository in context, and each found what the previous one was not looking at. That is
evidence the method works and equally that it is bounded — this round found the spike because the
spike was new, not because a cold reader would start there.
