## 1. Verdict

**The repository is stronger than round 7 left it, and stronger than it currently says it is.**
Every fixable finding round 7 raised in `scripts/spike2a/` was fixed on `main` in the interval,
including the two whose fixes this round could verify by mutation rather than by reading: H5's
window/selection join (`scripts/spike2a/sample.py`) and H3's hand-derived-R regression, which now
has a direct guard (`tests/test_spike2a_instrumentation.py`). Both were confirmed by reintroducing
the original defect and watching the test fail. Separately, PLAN D30 landed a provenance gate
(`scripts/spike2a/provenance.py`) in front of all six spike entry points and a twenty-root import
denylist across `src/`, `scripts/` and `tests/`, both enforced by tests in
`tests/test_enforcement.py` that this round ran rather than read.

The one thing this round found is that the fix for H3 was not reflected in the two documents whose
job is to describe exactly that gap. `docs/PLAN.md`'s risk register and
`scripts/spike2a/README.md`'s guardrail section both still say — after the commit that closes it —
that the hand-derived-R defect "would still not be caught" and is "guarded by nothing at all."
Both statements were true when first written (round 7, before D30) and became false in the same
commit that added `tests/test_spike2a_instrumentation.py` (`e28bf55`), which did not update either.
This is round 7's H1 with the sign flipped: H1 was a document claiming a guardrail held when
`make check` was red; I1 is two documents claiming a guardrail does not exist after it was built
and shipped in the same change. A document being wrong in the safe direction is still wrong, and
the safe direction has a real cost here — a reader following `scripts/spike2a/README.md` today
would conclude the R-derivation defect needs a fresh fix, when it needs a fresh regression test
added if the check is ever widened.

**Is the project up to par?** Yes, on every axis this round could check. `src/tradipy/` is
unchanged and `make check` is green at `b70fa7a` — ruff, format, basedpyright, the link checker
(175 links) and pytest (154 test functions / 194 cases across nine files) all executed by this
review, not cited from a previous one. The spike instrumentation, which round 7 found to be the
least-checked code in the repository, now carries two purpose-built guarantee tests
(`test_spike2a_sample.py`, `test_spike2a_instrumentation.py`) whose stated attack was verified by
this review to actually fail without the guard, in three cases each — six mutations attempted,
six caught.

**What this round did not do.** It did not reread `docs/PRD.md` end to end — at over the
character budget for a single pass, and with zero diff in the code it governs since the round that
did read it fully, a full reread would have reproduced round 7's PRD-alignment findings rather than
found new ones. It did not run a mutation-testing tool (H13 remains unanswerable for the same
reason round 7 left it that way) and did not attempt Workstream 11's still-outstanding cold read.

## 4. Findings

### I1 — LOW-MEDIUM — two documents understate a fix that shipped in the same commit as D30

**What is claimed.** `docs/PLAN.md` (§ Risks & Dependencies, "The instrument is outside every
check"): *"The hand-derived R that moved the verdict from INERT to CALIBRATED would still not be
caught. Continue to treat every spike number as unverified."* `scripts/spike2a/README.md` (line
170, before this fix): *"The second obligation below is guarded by nothing at all, and it was the
round-7 defect with teeth."*

**What is actually enforced.** `tests/test_spike2a_instrumentation.py`, added in `e28bf55` — the
same commit that both documents' surrounding D30 material describes — contains
`test_generate_signal_bars_calls_apply_stop_floor_and_ceiling` (an AST check that
`generate_signal_bars` calls `gates.apply_stop_floor_and_ceiling`) and
`test_signal_bar_r_equals_entry_minus_library_stop` (a runtime check that every generated R equals
entry minus the library's own stop). Together these are a direct guard against exactly the H3
regression both documents describe as uncaught.

**How reproduced.** By mutation, twice. `synthetic_data_generator.generate_signal_bars`'s R
computation was edited back to the original H3 shape — `entry * Decimal("0.02")` in place of the
call to `apply_stop_floor_and_ceiling` — and both new tests failed immediately with the guard
removed, then passed again once it was restored. This is the same experiment round 7 ran to find
H3 in the first place, rerun against the fix.

**Why it is LOW-MEDIUM, not higher.** No behaviour changed and no spec question is implicated —
the code is more correct than either document says. The cost is that a reader relying on either
document would misjudge how much independent verification the R-derivation obligation still needs,
in the safe direction (overcaution) rather than the dangerous one (false confidence) — the reverse
of H1's severity driver, which is why this is not rated HIGH the way H1 was.

**Disposition.** Fixed in this change — both documents now state that the specific H3 regression
is caught by `test_spike2a_instrumentation.py`, while preserving the accurate, narrower claim
underneath (provenance and the schema still say nothing about arithmetic correctness in general,
and no mechanism generalizes this specific guard to other spike-derived values). Per convention 8:
no `docs/CHANGELOG.md` entry (no spec question), no root `CHANGELOG.md` entry (no code changed).

## 6. The risk the findings list does not capture

**The spike's test coverage is now good enough that it invites reading it as equivalent to §21.1
coverage, and it is not.** `test_spike2a_instrumentation.py` and `test_spike2a_sample.py` are
real, mutation-verified guarantee tests — but they are two hand-picked guards against two specific
defects a human reviewer already found (H3 and H5), not a coverage obligation that would have found
a *third*, undiscovered one. PHASE-2A-SPIKE §8's exemption is exactly as wide as it was in round 7;
what changed is that two specific holes in it were patched, not that the hole itself narrowed. The
risk is that the presence of `tests/test_spike2a_instrumentation.py` now reads, to a future skim,
like "the spike has tests" in the sense `src/tradipy/` does — a coverage obligation with a
denominator — when it is closer to two point fixes with a name that sounds systematic. Nothing in
this interval's commits claims otherwise, but I1's own shape (a document overstating how *un*guarded
something is) shows the failure runs in both directions, and this is the version of it that could
happen next: a document overstating how *guarded* the spike now is, in general, from two specific
guards.
